# MLB 每日勝率預測系統

一套可重複使用的 Python 工具,依據**賽季戰績、主場優勢、先發投手戰力、傷兵嚴重度**四項變因,計算隔日賽事主隊勝率。

## 🌐 想要不開電腦、隨時用手機看?

有一個**雲端全自動版**,設定一次後,每天自動更新,產生一個永久網址,手機電腦隨時打開瀏覽器就能看,完全不用開自己的電腦。設定步驟看 **`雲端自動化設定教學.md`**(約10分鐘,全部免費)。以下是「在自己電腦上跑」的傳統版本說明。

## 🚀 三種使用模式(電腦本機版)

| 檔案 | 用途 | 會不會自動開瀏覽器 |
|---|---|---|
| `每日執行.bat` | 手動雙擊,馬上看今天預測 | ✅ 會 |
| `核對昨日戰績.bat` | 手動雙擊,馬上看昨天猜得準不準 | ✅ 會 |
| `背景更新.bat` | **適合排程自動執行**,只更新資料+存成網頁檔,你自己找時間看 | ❌ 不會 |

**想要「自動更新資料,但自己找時間手動點開看」**:把 Windows 排程指向 `背景更新.bat`(見下方「設定每日自動執行.md」),它會在背景默默抓資料、算勝率、順便核對昨天命中率,全部寫進 `report.html` 和 `verify_report.html` 兩個檔案,但**不會自動彈出瀏覽器**。想看的時候,直接到資料夾裡雙擊 `report.html` 或 `verify_report.html` 就能打開(平常瀏覽器怎麼開網頁檔,這裡就怎麼開)。執行紀錄與錯誤訊息會寫進同資料夾的 `update_log.txt`,方便你回頭確認有沒有正常跑。

**想要「跑完立刻自動跳出來看」**:雙擊 `每日執行.bat` 或 `核對昨日戰績.bat` 即可,適合臨時想看的時候用。

## 環境需求

- Python 3.7 以上(無需安裝額外套件,全部使用標準函式庫)

## 命令列用法

```bash
# 全自動:抓即時戰績+對戰表+先發投手,並產生網頁報告自動開啟
python mlb_predictor.py --live --html

# 只想看終端機文字報告,不用即時資料(用 data/ 內建範例資料)
python mlb_predictor.py

# 指定要預測哪一天(預設是明天)
python mlb_predictor.py --live --html --date 2026-09-25

# 只產生網頁報告檔案,不自動跳出瀏覽器
python mlb_predictor.py --live --html --no-open

# 將結果匯出成 CSV(可用 Excel 開啟)或 JSON
python mlb_predictor.py --live --export-csv predictions.csv
python mlb_predictor.py --live --export-json predictions.json

# 核對「昨天」的預測是否命中實際戰果(自動抓實際比分比對)
python mlb_predictor.py --verify --html

# 核對指定日期的預測命中率
python mlb_predictor.py --verify 2026-09-23 --html
```

## 核對命中率是怎麼運作的?

每次執行預測(不論有沒有加 `--live`),系統都會自動把當次的預測結果存進 `data/history/YYYY-MM-DD.json`。

之後執行 `--verify`,系統會:
1. 讀取該日期存好的預測記錄
2. 向 MLB 官方 API 抓該日期所有比賽的**實際比分**
3. 逐場比對「預測贏的隊伍」是否等於「實際贏的隊伍」
4. 算出整體命中率,以及**高信心場次**(預測勝率≥65%或≤35%的場次)命中率——這組數字更能反映模型的判斷力道夠不夠準

⚠️ 注意:只有你**曾經用本程式跑過預測**的日期,才會有記錄可供核對。如果某天沒開電腦執行 `每日執行.bat`,那天就沒有預測記錄,`--verify` 會提示找不到資料。

## 準確率怎麼看?

這套系統**沒有預先寫死的準確率**——它是量化模型,不是拿大量歷史資料訓練過的機器學習模型,所以現在準不準只能靠你自己用出來、累積出來。參考值:單場棒球比賽本身隨機性就很高,就算是專業博彩公司的模型,單場預測準確率通常也落在55~65%之間。

雙擊 **`查看準確率.bat`**,會自動掃描 `data/history/` 裡所有存過的預測記錄,逐日向 MLB API 抓實際戰果比對,列出**每一天**的命中率,以及**累積至今的整體命中率**跟高信心場次命中率。建議累積 **2~3週、30場以上**的資料再看整體數字,場次太少會大起大落沒有參考價值。

## 現在有了 `--live`,還需要手動更新資料嗎?

- **對戰表與先發投手**:`--live` 會自動抓,不用再手動編輯 `matchups.json` 了。只有在抓取失敗(斷網、MLB API異常)時才會退回讀取這個檔案當備案。
- **戰績**:`--live` 會自動抓,同樣失敗才退回本地檔案。
- **投手戰力評分**:`--live` 模式現在也會自動算了!系統會用MLB官方API抓每位先發投手本季的原始數據(局數、三振、保送、被全壘打),自己換算出真正的**FIP(防禦率獨立指數)**,再轉成1~10分戰力評分,不再是主觀估計。詳見下一節說明。
- **傷兵分數**:MLB官方API沒有公開這項的乾淨數據源,**目前仍需手動更新**(見下方說明)。若不更新,系統會用預設值(60分,聯盟平均),準確度會打折但仍可運作。

## 投手戰力現在怎麼算?(FIP自動換算)

`--live` 模式下,每場比賽的兩位先發投手戰力分數,計算優先順序如下:

1. **MLB API即時算FIP**(主要來源):抓該投手本季至今的局數、三振數、保送數、被全壘打數,套用標準FIP公式:
   ```
   FIP = (13×被全壘打 + 3×保送 − 2×三振) ÷ 局數 + 3.10
   ```
   FIP是比單純ERA更能反映投手真實實力的指標(排除野手守備、運氣等球隊因素干擾),再用以下公式轉成1~10分:
   ```
   戰力分數 = 6.0 − (FIP − 4.10) × 1.8   (4.10為近年聯盟平均FIP的近似值)
   ```
2. **局數太少時(小於15局)**:樣本不可靠(例如球季剛開始、剛升上大聯盟的新人),改用下一順位。
3. **`data/pitcher_ratings.json` 手動分數**:如果MLB API查無資料(新人未建檔等情況),改讀這個檔案裡你自己填的分數。
4. **聯盟平均(6.0分)**:以上都沒有時的最終備援值。

這代表 `data/pitcher_ratings.json` 現在的角色從「主要資料來源」變成「備援名單」——大部分有出賽紀錄的投手都會被MLB API自動抓到,只有極少數新人或資料缺漏的情況才會用到這個檔案裡的手動分數。想手動蓋掉某位投手的分數(例如剛從傷兵名單回來,你認為API算出來的數字不準),一樣可以編輯這個檔案,系統仍會保留備援機制。

⚠️ FIP公式裡的常數 `3.10` 每年實際數字略有變動(通常在3.0~3.2之間),已在程式最上方定義成 `FIP_CONSTANT`,想更精確可以自行查當季實際數字更新。

## 模型邏輯說明

```
最終勝率 = Log5(主隊賽季勝率, 客隊賽季勝率)
           轉換賠率後疊加主場優勢(聯盟平均主場勝率 54%)
           + (主投手戰力 − 客投手戰力) × 0.018
           + (客隊傷兵分 − 主隊傷兵分) × 0.0009
```

權重(`PITCHER_WEIGHT`、`INJURY_WEIGHT`、`HOME_FIELD_ADVANTAGE`)都定義在 `mlb_predictor.py` 檔案最上方,可依自己回測結果調整。

## 已知限制

1. 投手戰力現在(`--live`模式)已用真實FIP數據自動換算,但球季初期或剛升上大聯盟的新人局數不足,仍會退回聯盟平均或手動備援分數
2. 傷兵分數是「陣容深度」代理指標,無法反映單場先發是否確定登板,且沒有公開API,仍需手動更新
3. 未納入:左右打對戰優勢、球場因素(如高海拔球場)、天氣、牛棚usage疲勞度
4. FIP公式裡的聯盟平均常數是近似值,並非每季即時更新的精確數字

## 延伸建議

- 可將 `data/pitcher_ratings.json` 改成串接 FanGraphs 或 Baseball Savant 的公開 API/爬蟲,自動計算 ERA、FIP、xFIP 加權分數
- 可寫一個 cron job 排程,每天早上自動執行 `--live` 更新戰績並寄送預測報告
- 可用歷史賽果回測(back-test)調整模型權重,讓預測更準
